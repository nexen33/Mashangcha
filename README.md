## 痛点与初衷：什么是“码上查”？

如果你平时在企业里做过财务做账、开票或者商务行政，一定经历过这种日常抓狂的场景：

在较为旧版的开票软件（如航信、百旺）或者财务核算系统（用友、金蝶等）里开具发票时，系统自带的下拉搜索框往往非常“死板”——既不支持按拼音首字母缩写搜，也不支持多个词拆开搜。手头管着几百上千家客户或供应商，只能在电脑后台常驻一份巨大的 Excel 企业信息对照表，反复按 `Ctrl + F` 查找、小心地双击复制编号和税号，再切回开票系统粘贴。

频繁来回切窗口不仅麻烦，而且一旦遇到 Excel 单元格被科学计数法搞坏成 `1.2345E+17`，或者复制时不小心带上了不可见空格，发票开错作废就成了家常便饭。更头疼的是，很多单位办公电脑还是十年前的 Windows 7 老机器，往往没有独立显卡驱动，装稍微现代一点的软件就弹各种“缺少运行库”、“入口点无法定位”的报错。

**“码上查” 就是为了彻底终结这些折磨而开发的一款支持悬浮置顶的检索工具。**

它就像一个永远静静停靠在开票软件身边的“便签条”，你不必离开开票界面，敲两下拼音简码就能瞬间搜出公司编号，鼠标轻轻一点或者敲一下回车（Enter），企业编号直接进剪贴板，点完马上按 `Ctrl + V` 就能粘贴，连多点一下鼠标激活输入框的动作都省了！

### 明确“码上查”不是什么

为了避免误解，在使用前请知悉：
- **它不是云端财务软件，不联网**：软件 100% 纯本地离线运行，没有后台服务器，绝不收集、上传任何企业商业数据。
- **它不注入或篡改开票软件**：不注入 DLL、不 hook 目标软件内存、不破坏任何税控系统的防篡改机制。
- **它不是臃肿的打包网页**：拒绝几十兆乃至上百兆的 Electron / WebView 框架，纯原生系统底层构建，只有一个仅仅 4MB 左右的独立 `.exe` 文件。

## 核心功能特色

### 1. 屏幕边缘常驻置顶，开票点击“绝不抢焦点”
- **悬浮置顶**：右上角开启置顶图钉后，窗口始终浮在最上层，不被任何财务全屏软件遮挡。
- **开票光标不丢**：当你在开票软件的“客户编码”输入框里看到光标闪烁时，直接用鼠标点击“码上查”里的卡片，**开票系统的输入焦点绝不丢失！** 点击后直接按键盘 `Ctrl + V` 瞬间粘贴，开票连击效率翻倍。
- **键盘回车盲操**：刚敲完拼音首字母，不想多一步鼠标操作？直接敲键盘 <kbd>Enter</kbd>（回车），第一顺位匹配到的企业编号自动复制进剪贴板。

### 2. 拼音首字母简码与多词灵活检索
- **拼音首字母缩写**：比如搜索“北京京东世纪贸易有限公司”，无需切换输入法，直接敲键盘 `jd` 或 `bjjdsj`，目标秒排第一位。
- **空格分隔多关键词**：同名或分支机构多时，输入 `华为 销售`（中间加空格），系统自动筛选既包含“华为”又包含“销售”的结果。
- **编号与税号模糊查找**：只记得客户编号尾号 `688` 或税号片段，直接输入数字同样迅速带出。

### 3. Excel / CSV 企业信息表格一键拖拽导入与智能识别
- **进销项独立隔离与前置确认**：软件对【进项】（供应商）与【销项】（客户）的企业信息实行完全独立的物理隔离存储。导入操作是严格针对当前正处于激活状态的分类生效的！因此在点击导入或拖拽表格前，**请务必先看一眼顶部正中间的滑块开关，点击确认当前停留在【进项】还是【销项】**。导入进项不会混淆或影响销项，反之亦然。
- **拖放即导**：确认分类后，把 Excel（`.xlsx` / `.xls`）或 `.csv` 文件直接拖进软件窗口，一秒完成录入。
- **智能表头对齐**：表格表头无论是叫“客户名称”、“单位抬头”，编码列叫“客户编码”、“企业代码”或“编号”，税号列叫“统一社会信用代码”或“纳税人识别号”，软件均能全自动精准匹配，无需手工重整表格。
- **无表头纯数据自然兼容**：如果平时导出的表格连表头行都没有，软件也能按照 `第1列企业名称、第2列企业编码、第3列税号（可选填入）` 的自然约定无缝导入。

### 4. 严格防呆防错拦截与一键查重复制
- **拦截科学计数法**：遇到 Excel 单元格被弄坏成 `1.23E+17` 这种浮点数时，软件立即弹窗阻断，绝不让坏数据混入企业库。
- **企业重名与编号重复拦截**：企业信息严禁同名或同号串户。导入时若发现冲突，软件立即标明冲突行数。点击【一键复制全部冲突明细】，可以直接粘回 Excel 迅速比对修改。

### 5. 尺寸任意拉伸与自适应记忆
- 搜索结果视窗的高度支持从默认的 **3 组** 展开至最多 **10 组**；宽度最大支持拉伸至 **150%**，再长的国企全称也能一览无余。
- 松开鼠标自动记住当前尺寸，下次开机打开依然是你最舒服的大小。

### 6. 随身 U 盘便携模式与硬件级数据加密
- **默认模式**：导入的信息自动绑定当前电脑的硬件指纹进行 `ChaCha20-Poly1305` 认证加密，别人拷走数据文件也绝对无法解密，保障商业机密安全。
- **便携 U 盘模式**：在程序同级目录下新建一个 `portable.flag` 文件，所有企业数据将直接加密保存在 U 盘内，随插随走，换电脑办公依然顺畅。

## 运行环境与极端兼容性

很多财务办公室使用的是年代较久的 Windows 7 电脑，缺少显卡驱动和 VC++ 运行库是常态。“码上查”从第一行代码起就为此做了极限适配：

| 环境维度 | 支持标准与技术实现 |
| :--- | :--- |
| **操作系统支持** | **Windows 7**（SP1 旗舰版/专业版裸机）、**Windows 8/10/11**（32位与64位全通吃） |
| **系统架构** | 原生 **32位 (x86 / i686)** PE 二进制，32位老系统原生执行，64位系统通过 WOW64 零损耗运行 |
| **运行库依赖** | **零依赖**。通过静态 CRT 链接（`+crt-static`），不需要目标机安装任何 VC++ Redistributable 或 .NET Framework |
| **图形与显卡要求** | **纯 CPU 软件渲染**。完全不依赖 Direct3D、OpenGL 或 Vulkan 显卡硬件加速，即使在虚拟机或未装显卡驱动的机器上也能直接秒开、不花屏、不崩溃 |
| **程序分发形态** | **单文件纯绿色版 (`Mashangcha_v1.0.0.exe`)**，体积仅约 4.4 MB，下载即用，不写注册表，随拷随走 |

## 安装与使用指引

### 1. 推荐部署方式（存放在 D 盘）
为避免平时电脑重装系统导致桌面或 C 盘文件遗失，推荐将程序保存在 D 盘：
1. 下载最新发布的 `Mashangcha_v1.0.0.exe` 单一文件，移动到你的 **D 盘**（例如新建文件夹 `D:\码上查\`）。
2. 将下载的 `Mashangcha_v1.0.0.exe` 重命名为更亲切简洁的 **`码上查.exe`**。
3. 在 `码上查.exe` 上点击**鼠标右键** → 选择 **【发送到】** → **【桌面快捷方式】**。
4. 以后每次办公，直接双击桌面上的“码上查”图标即可秒开使用！

### 2. 第一次导入企业信息（3 步上手）
1. 打开“码上查”，**首先看一眼顶部正中间的滑动开关，点击确认当前停留在【进项】还是【销项】**。
2. 点击右上角设置齿轮 `[⚙️]`，点击【导入数据 (Excel/CSV)】，或者**直接把你的企业信息表格 Excel 拖进软件窗口**。
3. 导入成功后，在中间搜索栏敲拼音首字母，目标立刻呈现！

## 常见问题解答 (FAQ)

#### Q1：点击卡片后开票软件界面没有失焦，这是正常的吗？
**答：这是本软件最核心的特色！** 置顶状态下点击只负责把内容放进剪贴板，绝不抢占输入焦点。请在点击后直接在开票软件里按 <kbd>Ctrl + V</kbd> 粘贴，习惯后操作极为流畅。

#### Q2：导入提示“发现重复企业名称或编号”被拒绝怎么办？
**答**：开票与做账严禁同名同号串户。弹窗出现后，直接点击红底弹窗里的【一键复制全部冲突明细】，去 Excel 里任意单元格按 <kbd>Ctrl + V</kbd> 粘贴，即可一目了然看清哪几行数据冲突，修正后再重新导入即可。

#### Q3：导出的 Excel 文件会把税号变成科学计数法吗？
**答**：绝对不会。“码上查”在导出时为所有编号与税号单元格强制应用了 `@` 纯文本格式防护，无论在哪个版本的 Excel 中打开，都不会丢失前导 0 或被误转为科学计数法。

#### Q4：设置中的“展示所有企业”是什么意思？为什么选择“未搜索时”只显示前 20 条？
**答：这是在易用性与极端老旧电脑能效之间做出的专业工程平衡。**
- **功能含义**：
  - **默认【禁用】**：在没有输入任何搜索关键词时，视窗保持清爽，仅显示中央的快捷搜索提示，不渲染任何卡片；右上角实时显示当前分类的企业信息总数（“共 N 条”）。键入关键字时才即刻匹配。
  - **开启【未搜索时】**：在搜索框为空时，系统也会默认在视窗中列出当前分类的前 20 条企业信息，方便用户直接点按高频企业，或在不敲字时快速核对最新录入的内容。
- **为什么严格限制为前 20 条（Top-20 截断）？**
  - **底层软件光栅化渲染保护**：为了实现在无独立显卡驱动的 Windows 7 裸机或老旧办公电脑上流畅秒开，本项目采用了纯 CPU 软件渲染架构。若在未搜索时一次性将几千乃至上万条企业信息全量实例化并构建到 UI 渲染树中，会瞬间引发无谓内存开销，并导致老旧 CPU 在绘制和滑动时出现掉帧甚至假死。
  - **极速响应**：截取 20 条（代码中通过 `MAX_SEARCH_RESULTS = 20` 严格控顶）既能保证内存占用恒定在毫秒级微开销、滚动极其丝滑，又能满足财务人员的日常搜索需要。一旦输入关键字，搜索算法会瞬间在全量企业信息库中完成过滤并呈现最精准的匹配项。
